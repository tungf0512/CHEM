# ADR-007: Separate physical cameras from capture modes

- Status: accepted
- Context: Enumerating physical and virtual AVFoundation devices as interchangeable “lenses” creates duplicate choices. A single physical Fusion Main camera can support distinct user-facing 1× and 2× sensor-crop modes; the iPhone Air is the first physical validation target. Future calibration must identify both the source sensor and its crop/mode.
- Decision: Use Strategy A (physical-device selection) and model `physicalDeviceID` independently from `CameraLens.id`, which identifies a user-selectable `CameraCaptureMode`. Enumerate physical rear Ultra Wide, Main/wide, and Telephoto devices; omit virtual dual/triple devices from the UI. Every physical device gets a base mode. A Main sensor gets a 2× crop mode only when the active AVFoundation format reports both a 2× video-zoom upscale threshold and a 2× maximum zoom factor. The mode applies `videoZoomFactor` to its physical device.
- Determinism: Sort semantic choices by displayed zoom, role, physical device ID, and mode ID; expose only one button per display zoom. Native acknowledges the selected mode. Capture metadata records mode ID, physical device ID, mode kind, and device-local zoom factor so future DeviceProfile calibration can distinguish a crop from another sensor.
- Consequences: A button no longer implies a separate `AVCaptureDevice`. The initial implementation uses only hardware-reported capabilities and does not branch on an iPhone model name. Physical switching/crop quality, still-photo crop behavior, and the iPhone Air’s exact supported zoom threshold still require device validation.
