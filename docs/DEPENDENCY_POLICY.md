# Dependency and generated-artifact policy

- `mobile/package-lock.json` is committed and `npm ci` is the JavaScript install path. Node is pinned by `mobile/.nvmrc` (`20.19.6`).
- iOS tooling uses the exact Ruby in `mobile/.ruby-version` (`3.4.11`). `mobile/Gemfile` reads that file directly so the Bundler Ruby requirement cannot drift from the setup-ruby input.
- Bundler is explicitly selected as `2.7.2` in the macOS workflow. Before installation, CI runs `bundle _2.7.2_ lock --bundler 2.7.2` so Bundler regenerates the lock metadata using the selected toolchain; the install and CocoaPods commands then explicitly invoke Bundler `2.7.2`. Lock metadata must be generated by Bundler, never hand-edited.
- CocoaPods is pinned to `1.15.2`, the version already present in the foundation lock, with the existing Xcode project parser constraints retained. This task stabilizes the toolchain rather than combining a CocoaPods/Xcode project-parser upgrade with the first native build.
- `mobile/ios/Pods/` and `mobile/build/` are generated and ignored; never commit them.
- React Native Codegen artifacts under `mobile/build/generated/` are generated during CI/build and are not committed.
- `mobile/ios/Podfile.lock` is source-controlled policy. The macOS workflow creates and uploads it as part of the `ios-foundation-lockfiles-<run-id>` artifact. If the runner artifact cannot be fetched from this environment, download it with authenticated GitHub CLI access and copy `mobile/ios/Podfile.lock` into the working tree before committing it. Do not fabricate or hand-edit the CocoaPods resolution.

The previous lockfile was generated on Linux Ruby `3.0.2p107` with Bundler `2.2.22`; CI had selected Ruby `3.2`. The second macOS run proved that Bundler `2.7.2` auto-restarted under the stale locked `2.2.22`, which crashes on Ruby `3.4.11` because `DidYouMean::SPELL_CHECKERS` no longer exists. CI now invokes Bundler `2.7.2` directly to regenerate its metadata before installation and preserves the runner-generated lock as an artifact for source-control handoff. The original CI artifact endpoint requires repository admin access, so lockfile retrieval must use an authenticated GitHub session.
